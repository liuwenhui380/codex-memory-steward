# 大记忆文件语义拆分规则

## 适用条件

- 将记忆文件标为拆分候选：行数 `>120` **或** UTF-8 字节数 `>12 KiB`（`12×1024`）。两项均未超出时不因大小拆分。
- 候选扫描只读；不得静默移动、删除或改写内容。先记录源文件、标题、行数、字节数和全部 usage marker。
- 拆分后的每个 detail 文件默认回答一个可独立召回的问题，并再次满足上述两个阈值；若确有必要超限，必须标注理由并继续细分。

## 主题边界与拆分顺序

按以下顺序确定边界，直到每个文件都能独立使用：

1. 优先沿 Markdown 二级、三级标题切块；保留标题下完整的说明、示例、约束和 marker。
2. 同一大类不得因为名称相近而合并。若标题内仍有多个独立问题，继续按语义拆分；自然边界不足时按具体服务、故障类型、操作阶段或时间段切分。
3. 常见独立主题包括：功能契约、部署/发布、故障恢复、隐私边界、测试/验证、历史归档。应写成“一个主题 = 一类决策或操作”，而不是“一个主题 = 一个宽泛领域”。
4. 下列内容必须分开：当前规则与历史事实；正常流程与故障恢复；公开配置与敏感信息处理；不同服务或不同故障类型；互不依赖的测试策略与发布步骤。
5. 只有为理解同一问题所必需的前置条件可留在同一文件；跨主题依赖改为短链接和一句上下文，不复制正文。

每个新文件使用稳定、可搜索的主题名（建议 `references/<area>-<topic>.md`），文件开头注明来源文件和主题摘要。原文件改为紧凑索引，只保留主题名、关键词、相对链接和一句简体中文摘要；路径、命令、commit、API 名称等技术标识保持原样。

## 可选的 Luna 语义计划

Luna 仅生成计划，不直接写入、移动或删除文件；没有 Luna 时由 Codex 按同一结构生成计划。发送给 Luna 前必须完成敏感信息门禁，输入只包含已过滤的标题、内容块标识和必要的非敏感摘要。

计划至少符合以下 JSON 形状（可增加字段，不得改变必填字段语义）：

```json
{
  "version": 1,
  "source": "references/memory.md",
  "candidates": [
    {
      "target_file": "references/deploy-release.md",
      "topic": "部署与发布",
      "keywords": ["部署", "发布", "回滚"],
      "blocks": ["## 部署", "### 回滚"],
      "summary": "记录部署、发布和回滚的可执行规则。",
      "reason": "该主题可独立召回，且与故障恢复边界不同。",
      "conflicts": []
    }
  ]
}
```

`blocks` 必须引用源文件中可定位的标题或内容块；`target_file` 不得与源文件冲突，且计划不得凭空扩展事实。`conflicts` 用于列出重叠主题、未决归属或需要人工判断的内容；存在冲突时暂停该块的自动拆分。

## 敏感信息门禁

在任何模型规划前，对候选文本和计划输入做本地扫描。命中疑似密钥、密码、令牌、Cookie、API key、私钥、凭据、带认证信息的 URL、原始私密会话或可识别个人敏感数据时：

- 不把命中内容或其可逆变体发送给 Luna；跳过 Luna 规划并要求人工处理。
- 不将秘密写入新文件、索引、摘要、关键词、日志或 marker；必要时只保留“存在敏感内容，需人工复核”的非敏感占位说明。
- 计划或拆分结果若引入疑似敏感值，立即拒绝写入并报告命中位置。

## 拆分执行与验收

按“计划 → 人工/语义审查 → 写入新文件 → 原文件索引化”的顺序执行；任何写入前确认目标在仓库根目录内，且不跟随仓库外链接或符号链接。

拆分后必须同时通过以下检查，否则回滚本次语义变更并报告原因（不得删除原内容来掩盖失败）：

1. **完整性**：源文件的标题和内容块均在索引或唯一目标文件中有覆盖；正文无遗漏、无重复搬运、无事实扩大或语言漂移。
2. **链接**：索引中的每个相对链接都指向存在的目标文件；目标文件中的内部链接也可解析，且不指向仓库外路径。
3. **marker**：原有 usage marker 的 ID、字段和值被保留；每个 ID 全局唯一、格式合法，未因拆分重复或丢失。新入口才可新增 marker，并使用稳定 ID。
4. **边界**：每个 detail 文件只含一个可独立召回主题；同一大类中仍含多个独立问题时继续细分。
5. **规模**：索引和所有 detail 文件重新统计行数与 UTF-8 字节数；任何超出 `120` 行或 `12 KiB` 的文件继续作为候选，不得宣称验收通过。
6. **安全**：再次扫描拆分结果、索引和计划，确认没有秘密、凭据或原始私密会话泄漏。

最终保留源文件到目标文件的映射和验证结果，供差异审查追溯；拆分规则本身不负责提交或推送。
