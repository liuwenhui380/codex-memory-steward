# 基于使用频率的渐进式记忆召回设计

日期：2026-07-12
状态：已实现并验证

## 1. 目标

优化 `codex-memory-steward`，让后续 Codex 只读取完成当前任务所需的最少记忆文本，同时保留可追溯、可验证的完整记忆体系。

本次改造必须实现：

- Codex 实际使用某个记忆入口后，自动更新调用次数和最后使用日期。
- 根据调用频率、最近使用时间和安全属性生成提升、下沉或归档建议。
- 根记忆只保留高频、安全关键规则和简短路由。
- 大文件即使属于同一大类，也要按可独立召回的具体主题继续拆分。
- Luna 可参与语义拆分，但不得成为必需依赖。
- 新增记忆默认跟随用户和项目语言；当前用户场景优先使用简体中文，技术标识保持原样。
- 保持旧 usage marker 和现有项目记忆兼容。

## 2. 不做的事情

- 不从完整聊天记录中猜测调用次数。
- 不让脚本独立决定语义内容应该移动到哪里。
- 不自动删除低频记忆。
- 不把密钥、密码、令牌、Cookie 或原始私密会话交给 Luna。
- 不要求项目安装额外 PowerShell 模块或固定使用某个模型服务。

## 3. 记忆层级

采用四层结构：

1. `root`：根 `agent.md`，目标不超过 80 行，只保留安全关键规则、高频规则和一级路由。
2. `index`：分类索引，目标不超过 80 行，每个主题只保留名称、关键词、链接和一句摘要。
3. `detail`：具体主题文件，默认不超过 120 行或 12 KiB，每个文件只回答一个可独立召回的问题。
4. `archive`：低频且长期未使用的历史事实，仍可通过索引找到，但不进入常规读取路径。

安全关键记忆使用 `pinned=true`，始终保留在 `root` 或直接可达的 `index`，不受低调用次数影响。

## 4. 调用次数记录

继续兼容现有格式：

```html
<!-- usage:agent.area.topic count=3 since=2026-06-01 last=2026-07-12 -->
```

允许追加可选字段：

```html
<!-- usage:agent.area.topic count=3 since=2026-06-01 last=2026-07-12 tier=index pinned=false -->
```

`run_memory_steward.ps1` 增加显式触达参数。技能在实际读取并使用某个记忆入口后调用该参数，只更新精确匹配的 ID：

```powershell
./scripts/run_memory_steward.ps1 -RepoRoot <repo> -TouchId agent.area.topic
```

规则：

- `count` 加一。
- `last` 更新为当前日期。
- 缺失 `since` 时补为当前日期。
- 找不到 ID、出现重复 ID 或 marker 格式错误时停止写入并报告错误。
- 普通扫描保持只读；只有显式 `-TouchId` 才修改项目记忆。
- 测试可注入固定日期，保证结果可复现。

## 5. 层级转换建议

脚本根据 marker 生成候选建议，并输出具体原因；真正的文件移动仍由 Codex 或经批准的语义步骤完成。

建议逻辑：

- `pinned=true`：固定为 `root` 或 `index`。
- 最近 30 天持续使用且调用密度高：建议 `root`。
- 最近 90 天使用或调用密度中等：建议 `index`。
- 偶尔使用但仍有明确价值：建议 `detail`。
- 从未使用，或超过 180 天未使用且调用次数不高：建议 `archive`。

调用密度按 `count`、`since` 和当前日期计算，避免只看永久累计次数。输出必须包含当前层、建议层和理由，不能直接静默迁移。

## 6. 大文件拆分

扫描器将超过 120 行或 12 KiB 的记忆文件标记为拆分候选，并提取标题、行数、字节数和 usage marker。

拆分遵循以下顺序：

1. 先按 Markdown 二级、三级标题识别自然边界。
2. 如果一个标题内仍包含多个独立问题，则继续按语义主题拆分，不能只因为属于同一大类就保留在同一文件。
3. 每个新文件使用稳定、可搜索的主题名，并保留来源索引。
4. 原文件变为紧凑索引，提供关键词、链接和一句中文摘要。
5. 拆分后验证标题覆盖、链接存在、marker 唯一、无重复内容、无内容丢失，并再次检查文件大小。

典型拆分维度包括功能契约、部署发布、故障恢复、隐私边界、测试验证和历史归档。若一个维度仍超过阈值，则按具体服务、故障类型或时间段继续拆分。

## 7. Luna 可选语义规划

Luna 只用于生成拆分计划，不直接写文件。输入是已经过敏感信息过滤的候选文件结构，输出为结构化计划，至少包含：

- 目标文件名。
- 主题名称和召回关键词。
- 应迁移的标题或内容块。
- 一句简体中文摘要。
- 原因和潜在冲突。

脚本保持模型无关，只负责导出候选信息和验证拆分结果。若当前环境没有 Luna，则由 Codex 使用相同结构生成计划；基础扫描、计数和层级建议不受影响。

## 8. 组件改动

- `SKILL.md`：改为最短入口，规定先扫描、按需读取、读取后 touch、再按建议整理。
- `scripts/run_memory_steward.ps1`：增加 marker 更新、层级建议、大文件候选和机器可读 JSON 输出，同时保留现有 Markdown 输出。
- `references/workflow.md`：记录四层结构、中文写入策略和最小召回流程。
- `references/tiering.md`：记录评分、固定规则和层级转换边界。
- `references/splitting.md`：记录具体主题拆分、Luna 计划格式和验证要求。
- `tests/run_tests.ps1`：使用临时目录验证计数、兼容性、重复 ID、层级建议和大文件识别，不依赖 Pester。
- `README.md` 与 `agents/openai.yaml`：更新公开说明和默认提示词。

现有工作区中“默认输出到 stdout，仅在传入 `-ReportRoot` 时落盘”的三处未提交修改与本设计兼容，实施时保留并纳入测试。

## 9. 错误处理与安全

- 所有写入先验证目标位于传入的 `RepoRoot` 内。
- 不跟随指向仓库外的链接或符号链接执行移动。
- marker 重复、日期非法或文件编码不可安全保留时拒绝修改。
- Luna 输入前执行敏感形态检查；命中疑似凭据时跳过模型拆分并要求人工处理。
- 拆分属于内容改写，必须使用差异审查确认没有事实扩大、遗漏或语言漂移。
- 技能仍不得自动提交或推送用户项目；只有用户明确要求发布技能自身时才允许操作技能仓库。

## 10. 测试与验收

至少覆盖：

- 旧 marker 可解析且更新后仍兼容。
- 同一 `TouchId` 每调用一次只增加一次。
- 不带 `TouchId` 的扫描不会修改文件。
- 未找到或重复 ID 时文件保持不变。
- `pinned` 记忆不会被建议下沉。
- 高频近期、低频过期和 `last=never` 获得预期层级建议。
- 超过行数或字节阈值的文件被识别，小文件不误报。
- 拆分后的索引链接全部存在，所有记忆文件低于配置阈值。
- 中文摘要策略不会翻译路径、命令、commit、API 名称等技术标识。
- `run_memory_steward.ps1` 原有报告模式和可选 `-ReportRoot` 行为不回归。

最终执行 PowerShell 测试、示例仓库端到端测试、`git diff --check` 和敏感信息扫描，然后提交并推送当前功能分支到 GitHub。
